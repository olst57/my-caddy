What ran: an xray client with a socks inbound on 10800 and a VLESS/REALITY
outbound with `serverName b.test`, dialing the host's own private address
<PUBLIC_IP-1>:443 so that the client's source address differs from Caddy's layer4
upstream dial (127.0.0.1 -> 127.0.0.1:19098). Captures on both hops, then the
xray access log.

Deviation D-2 (scoring relevant): the spec's recipe is outbound
`"sendThrough": "<PUBLIC_IP-4>"`. This xray build accepts that key and does not
apply it: with `sendThrough` set to <PUBLIC_IP-4> a plain freedom outbound still
arrives at the listener from 127.0.0.1, and an impossible value
(`999.999.999.999`) still passes `xray run -test`. The probe is at the end of
this file. The substitute source address <PUBLIC_IP-1> is a strictly different
address from the l4 dial address, so the validity precondition the spec states
("client source must differ from the l4 outbound address") is met, by a
different mechanism than the one suggested.
