# REALITY end-to-end harness

`tests/e2e/` turns the 2026-11-06 hand-run REALITY round into assertions that
run from this repository. It is a **separate suite**: it does not add items to
`scripts/verify.sh` (26 offline) or to `tests/coexist/` (CO-1..CO-8), and the
frozen delivery tree is read-only to it.

The harness derives its Caddyfile from `deploy/Caddyfile` by literal
substitution, reverses every substitution, and diffs the result against the
delivery file. A non-empty diff aborts before a single listener starts, so a
green run is a statement about the delivery shape, not about a hand-written
test config.

## Ports

| Port | Role | Bound by |
|---|---|---|
| `8443/tcp` | the Caddy listener (stands in for the delivery `:443`) | Caddy |
| `19099/tcp` | REALITY inbound | Xray server, or the PROXY v2 stub |
| `18080/tcp` | site reverse_proxy upstream and the tunnel's inner target | `site-backend.py` |
| `18081/tcp` | counting target for the naive ACL and credential checks | `backend-counting.py` |
| `10802/tcp` | SOCKS inbound of the Xray client | Xray client |

`443` and `19098` are deliberately not touched: the harness refuses to start if
`8443`, `19099`, `18080`, `18081` or `10802` is already in use.

The harness needs **root**, because Caddy binds `8443` and its internal CA has
to be created under the work directory.

## External inputs

Four things are uploaded to the test host instead of being downloaded there:

1. the Caddy binary, built with `forwardproxy` and `caddy-l4`;
2. the Xray binary used as the REALITY server;
3. the Xray binary used as the SOCKS client;
4. the REALITY destination choice: a `host:port` reachable from the test host
   whose certificate is valid for the chosen SNI.

Everything else is generated on the host: the naive credentials are random per
run, and the REALITY key material is generated by the Xray binary when the four
key variables are unset.

The server template's `freedom` outbound carries one explicit, test-only
`finalRules` entry: it allows TCP to `127.0.0.1:18080`, the inner target. Xray
26 otherwise treats a loopback destination as private and blackholes it, which
would make E2E-01 fail before the tunnel's payload is exercised. The rule is
scoped to this fixture; it is not a production recommendation.

The E2E Caddyfile also substitutes the delivery file's `probe_resistance`
domain with `localhost` for the run. The wrong- and missing-credential items
ask for `localhost:<target-port>`; forwardproxy's probe-resistance branch then
serves its built-in decoy page without dialing the counting target. If a
future regression tunnels the request instead, `localhost` reaches the same
counting target and makes the counter delta nonzero. The delivery file is not
changed; the substitution is reversed with the other overlay edits.

The test overlay also inserts the global `debug` directive and removes it
during the reverse diff. forwardproxy returns a CONNECT `200` before its ACL
lookup, and Caddy records the subsequent `no allowed IP addresses` error at
debug level only. The private-target item therefore reads a scoped debug log
window; the delivery file keeps its normal log level. The private-target probe
also sends a plain HTTP GET inside the tunnel. If an allow rule reaches the
overlay, the counting target records that request and returns its marker, so
the item is red independently of the log line.

## Required environment

| Variable | Meaning |
|---|---|
| `CADDY_BIN` | Caddy built with `forwardproxy` and `caddy-l4` |
| `E2E_XRAY_SERVER_BIN` | Xray binary for the REALITY inbound, also used for key generation |
| `E2E_XRAY_CLIENT_BIN` | Xray binary for the SOCKS client, also used for control keys |
| `E2E_REALITY_SNI` | outer SNI the client sends and the layer4 matcher claims |
| `E2E_REALITY_DEST` | `host:port` the REALITY inbound falls back to |
| `E2E_TARGET` | `http(s)://` URL fetched through the SOCKS inbound |
| `E2E_TARGET_MARKER` | body marker only that target produces |

A missing or empty value is exit `2` naming the variable; there is no skip
path. `--negative-preflight` proves that for every variable.

Optional, all-or-nothing: `E2E_REALITY_UUID`, `E2E_REALITY_PRIVATE_KEY`,
`E2E_REALITY_PUBLIC_KEY`, `E2E_REALITY_SHORT_ID`. With all four unset the
harness generates them at run time. Supplying a subset is a hard failure: a
half-injected key set is ambiguous, and topping it up silently would hide the
mistake.

`E2E_WORKDIR` (default `.gate/e2e`), `E2E_TIMEOUT` (default 25 seconds) and
`E2E_CONTROL_TIMEOUT` (default 90 seconds) are tuning knobs, not inputs. The
negative controls need the larger budget because Xray's REALITY retry loop can
take longer than an ordinary request to surface the rejection.

## Modes

```text
bash tests/e2e/run.sh --preflight-only       # inputs, ports, overlay, adapt, configs
bash tests/e2e/run.sh --negative-preflight   # fail-closed tablature, starts nothing
bash tests/e2e/run.sh                        # the full run (root)
```

`--negative-preflight` needs no destination, no binary and no root: it only
re-invokes the preflight with one value removed or blanked and asserts exit `2`
before any process exists.

## Items

| Item | Assertion |
|---|---|
| `E2E-01` | A `curl` through the SOCKS inbound returns `200`, the target marker and `X-Site: e2e-inner`; no `alert 40` in the client log; no layer4 `EOF` in the Caddy log for the item window. A transient first request is retried up to three times; a request that never satisfies all facts is red. |
| `E2E-02` | The probe through the listener is TLS 1.3 with ALPN `h2`, and its SAN set, issuer, validity window and leaf sha256 match a live fetch of the destination. Transient live-fetch timeouts are retried; every required comparison must still pass. |
| `E2E-03` | The layer4 upstream records a PROXY v2 header with the `0d0a0d0a` signature, version/command `0x21`, family `0x11`, a 12-byte IPv4 address block, the expected destination, and an intact ClientHello carrying the SNI. |
| `E2E-04a` | A wrong UUID opens no tunnel; the client is still alive and the scoped client-or-server log names a handshake-class failure. |
| `E2E-04b` | Same, with a wrong publicKey. |
| `E2E-04c` | Same, with a wrong shortId. |
| `E2E-05a` | A wrong naive credential for the test decoy name returns the hidden-page marker, never the target marker, and the counting target's byte count does not change. |
| `E2E-05b` | The same three facts hold when no `Proxy-Authorization` is sent. |
| `E2E-05c` | A correct credential cannot reach the private target: a GET sent inside the CONNECT stream produces no target marker and no counter change, and the scoped debug log carries `no allowed IP addresses` with status `403` in the item window. |
| `E2E-07` | An unmatched, empty, or absent SNI is rejected: no handshake, no certificate field, and no new layer4 record. |

The run ends with `E2E: PASS` only when all ten items passed, and the closing
positive control (the passing client, re-run after the three controls) still
returns the marker.

The opening and closing positive controls retry transient SOCKS/Xray failures
up to three times. A failed attempt is printed; a control that never returns
the target marker remains a failure.

Before the REALITY client starts, the harness measures the
unknown/empty/absent SNI cases against the site listener, prints the three
`E2E-07 BASELINE` JSON objects, and then asserts them as `E2E-07`. Each record
carries the handshake, certificate subject and SAN, issuer, sha256, and the
layer4 record delta. All three must show `handshake=false`, a zero layer4
delta, and no certificate field; an error fragment is required per case
(`alert` for unknown and absent, `servername` for empty).

**The posture is `reject` (decided 2026-11-07).** It is what the delivery file
already does — no catch-all site, no `tls` fallback — so the item freezes
measured behaviour instead of inventing it, and `deploy/Caddyfile` stays
frozen. Choosing `decoy` or `default` later is a separate, explicitly approved
change to that file plus the S7-18 amendment.

The empty case is a documented **client** limitation: the probe's TLS client
refuses to build a zero-length `server_name` extension, so no record reaches
the listener. The item asserts that limitation and says so in the output rather
than claiming a server-side rejection it never observed.

## What this does not prove

- Production certificate chains, production decoy content and production
  hostnames: the run uses a self-signed internal CA and a throwaway SNI.
- Long soaks, concurrency and resource exhaustion: that is `E2E-08`, Phase 6.
- DPI resistance, TLS-in-TLS fingerprints and traffic shaping.
- That a valid empty-SNI ClientHello is rejected: the probe cannot construct
  one, so `E2E-07` covers the client's refusal, not the listener's handling of
  a hand-built extension.

## Files

| File | Role |
|---|---|
| `run.sh` | preflight, overlay derivation, stack, the ten items |
| `lib.sh` | `item`, `stop_pid`, `cleanup`, `port_busy`, `wait_records`, `require_env` |
| `negative-controls.sh` | renders the three single-field client mutations |
| `site-backend.py` | the site upstream and the tunnel's inner target |
| `backend-counting.py` | loopback target that appends one JSON line per accepted request |
| `naive-tunnel.py` | raw CONNECT probe for the decoy, missing credential, and private-target ACL cases |
| `probe-sni.py` | unknown, empty, and absent SNI probe behind `E2E-07` |
| `xray-server.tpl.json` | REALITY inbound template; no values |
| `xray-client.tpl.json` | SOCKS + single VLESS outbound template; no values |
| `probe-cert.py` | fetches and compares the presented certificate |
| `proxyv2.py` | parses the PROXY v2 header by field |
