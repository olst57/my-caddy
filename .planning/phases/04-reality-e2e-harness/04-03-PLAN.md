<threat_model>
T-4-07: A negative control mutates two fields, so a failure cannot be
attributed to either one.
Mitigation: each control renders its own client config from the passing
template with exactly one substitution, and the diff between the passing and
the control config is asserted to be one line.

T-4-08: The negative control passes because the client failed for an unrelated
reason (missing binary, busy port, bad template).
Mitigation: the control requires a positive control in the same run, and
requires the failure to be a TLS/handshake failure rather than a client
startup error; the client exit reason is classified.

T-4-09: The harness is added to CI and fails every run for lack of a
destination, so the maintainers disable it.
Mitigation: CI only runs `bash -n` and `python3 -m py_compile` over the
harness; the docs state that execution requires the Linux host.
</threat_model>
