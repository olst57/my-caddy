<threat_model>
T-5-03: The guard matches a comment line and reports a false failure, so it
gets disabled.
Mitigation: strip `#` comments and leading whitespace before matching site
address lines, exactly as CO-8 does for `probe_resistance`.

T-5-04: The guard is satisfied by a fixture that has the dual address but no
protocol pin, so h3 silently returns to the test stack.
Mitigation: both conditions are separate sub-assertions of one item, and both
must hold for every non-443 site block.

T-5-05: Raising the gate from 26 to 27 silently rewrites the historical
`v0.4.3` evidence, which recorded 26 items, and contradicts the milestone's
own success criterion that the offline gate still reports 26/26.
Mitigation: the item set defined by the SPEC stays frozen at 26. The guard is
a separate check with its own count, not a 27th item, and `v0.4.3` evidence
and release notes are never edited.

T-5-06: The separate check is added to CI and then drifts from the preflight
path, so one passes while the other fails.
Mitigation: `tests/fixtures/check.sh` is the only implementation; CI calls it
and the harness preflight calls it, rather than each re-implementing the rule.
</threat_model>
