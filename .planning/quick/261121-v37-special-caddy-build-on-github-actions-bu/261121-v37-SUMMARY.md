# Quick Task Summary: Special Caddy build on GitHub Actions

**A second, artifact-only build path now exists: Caddy `v2.11.9` plus only the
forwardproxy module, produced by a manual GitHub Actions workflow from a new
`SPECIAL_`-prefixed pins file. The delivery build, its pins, the patch surface,
the delivery Caddyfile and the four existing workflows are byte-identical to
`HEAD`. All offline checks passed on the Windows authoring host; the real build,
the native version/module assertions, the cross-arch structural checks and the
checksum verification are DEFERRED to the dispatched workflow run.**

## What Was Built

### `pins/special-build-inputs.env` (new)

Exactly five fixed keys, for example `SPECIAL_CADDY_TAG=v2.11.9`,
`SPECIAL_CADDY_COMMIT=0d98caea58f794f88e709b1bef2880996a471bca`,
`SPECIAL_FWDPROXY_SHA=e747854e78743dba85c039b38ed185fb11d93667`,
`SPECIAL_XCADDY_VERSION=v0.4.7` and `SPECIAL_GO_VERSION=1.26.9`. The header states
that this is the artifact-only special build, not the delivery pin surface; that
the delivery build and Gate 0 read `pins/build-inputs.env` and
`tests/pins/check.sh` never reads this file; that the `SPECIAL_` prefix makes an
accidental source fail on unset delivery variables; and that Caddy v2.11.9
already ships the idle-timeout override API, so this build needs no patch and no
source-replacement flag.

### `scripts/build-special.sh` (new)

Mirrors `scripts/build.sh` shape with a separate source tree
(`.build/caddy-special-src`). Order of operations:

- Sourcing the special pins file, then writing the effective values back into the
  `SPECIAL_` names so the build line and receipt share one value.
- Strict argument parsing (`--arch amd64|arm64|all`, `--print-pins`); unknown
  arguments and a missing `--arch` value die with the offending token.
- Shape checks on the two 40-hex commits, the two `vX.Y.Z` tags and the Go
  version.
- `--print-pins` exits before every Go and git command, which is what makes the
  script usable on a Windows host without a toolchain.
- `GOTOOLCHAIN=local` plus an exact `go1.26.9` check; a missing toolchain fails
  with the observed empty value.
- Clone `v2.11.9` depth 1, assert the head equals the pinned commit, assert
  `git diff --quiet` (a dirty tree means modifications were applied and this
  build must stay unpatched), and assert both idle-API symbols:
  `func (r *IdleTimeoutReader) Override(` and `func IdleTimeoutsFromContext(` in
  `modules/caddyhttp/idletimeout.go`.
- Unconditional `go install` of xcaddy `v0.4.7`, invoked by absolute path.
- Exactly one xcaddy build line and exactly one module-add option; no
  source-replacement flag and no layer 4 fork reference exist in the file.
- Native-arch verification runs `version` (anchored, dot-escaped tag) and
  `list-modules` (exact `http.handlers.forward_proxy`; the three layer4 modules
  must be absent, and a violation prints the observed value). Cross-arch
  verification is structural only (`go version -m` build info must record
  `GOARCH=<arch>` and `GOOS=linux`).
- `SHA256SUMS` covers only the requested `caddy-special-linux-*` set; the
  receipt `dist/special-pins.txt` records `patch=none`, the asserted module and
  the absent module set.

### `.github/workflows/build-special.yml` (new)

`name: build-special`; `on:` contains only `workflow_dispatch` with a closed
`arch` choice input (`all` default, `amd64`, `arm64`); `permissions: contents:
read`; one `GO_VERSION: 1.26.9` declaration; the same three pinned action
commits as `build.yml`. Steps: invoke `scripts/build-special.sh --arch "$ARCH"`,
cross-check seven fixed-string exact lines in `dist/special-pins.txt` against
`pins/special-build-inputs.env`, show the checksums and receipt, validate the
artifact set and run `sha256sum -c SHA256SUMS`, then upload only the two
binaries, the checksums and the receipt with `if-no-files-found: error`. No
release, tag, signing, container or publish step.
