# Quick Task 261121-v37: Special Caddy Build on GitHub Actions

<objective>
Add a second, artifact-only build path: Caddy v2.11.9 with only the forwardproxy module, produced by a manual GitHub Actions workflow from new SPECIAL_-prefixed pins. This build has no patch, no source-replacement flag, and no layer 4 module.
Purpose: prove a forwardproxy-only Caddy artifact can be built from the newest upstream tag without touching the delivery build, the delivery pins, the patch surface, or the single-listener delivery Caddyfile.

Output: `pins/special-build-inputs.env`, `scripts/build-special.sh`, `.github/workflows/build-special.yml`, and a summary that records observed offline output and lists the runtime checks deferred to the dispatched run.
</objective>

<context>
Read this plan with the working directory at the repository root. Every path in the task bodies, `files`, `verify` and `automated` commands is repo-root-relative. Only the source material named in the planning request is absolute.

Settled facts, verified 2026-11-21 with `gh api` from the authoring host:

- Caddy release `v2.11.9` was published 2026-11-05. Annotated tag object `a356e5048bf0059a7b7bdc10f7823d410bd8d86b` peels to commit `0d98caea58f794f88e709b1bef2880996a471bca`, which is the value to pin.
- The forwardproxy fork branch `naive` head is `e747854e78743dba85c039b38ed185fb11d93667`, identical to the delivery forwardproxy pin. Do not use the fork's `master` branch.
- xcaddy `v0.4.7` and Go `1.26.9` are also the delivery pins.
- Caddy `v2.11.9` source already ships `modules/caddyhttp/idletimeout.go` with `func (r *IdleTimeoutReader) Override(` and `func IdleTimeoutsFromContext(`. Those two symbols are the evidence that this build needs no patch and no source-replacement flag. Do not attribute the idle API to any other commit.

Anti-pattern: `scripts/build.sh` is the delivery build. Mirror its shape, logging, pin handling, absolute-path xcaddy invocation and native/cross verification, but do not copy its patch application, its source-replacement flag, its layer 4 module add, or its source directory. The special build must be a separate script with a separate source tree and a separate output name.

Host reality: this authoring host is Windows with Git Bash, jq, node and gh. It has no Go, no xcaddy, and cannot execute a Linux ELF. The only green evidence available here is offline shape checking. The real build, the native version/module assertions and the cross-arch structural checks happen only in the dispatched GitHub Actions run. Record them as DEFERRED, never as PASS.

Delivery checks: `tests/pins/check.sh` reads only `pins/build-inputs.env`, requires the four known workflows to declare `GO_VERSION` exactly once, and compares the delivery `--print-pins` output. It never reads the new pins file or the new workflow, so adding them is safe. The existing delivery build workflow triggers on pushes to `main` that touch `pins/**` or `scripts/**`, so merging this plan will also run the delivery build. That is expected; it is not a failure of this plan.

`scripts/verify.sh` hardcodes `v2.11.7` and must never be pointed at the special binary. Keep the special artifact names and the workflow comment explicit about that.

Redaction: `docs/REDACTION.md` defines the exact-token allowlist. The S7-13 scan in `scripts/verify.sh` extracts host tokens with `git grep --untracked` and the exact regex, sorts them, and compares against the 19 allowlist entries. Only allowlisted host tokens may appear in the new files or in this plan. Do not write a bare repository host; write the full module paths that the allowlist already covers.

No external API integration: the build consumes pinned Git repositories and Go modules. It adds no API, SDK or service surface, so there is no coverage matrix.

Assumption delta: add-alongside. The delivery identity model is unchanged. The special build is a parallel artifact producer; it shares no Caddyfile, no patch and no release channel, and its pins live in a `SPECIAL_`-prefixed file that the delivery checks never read. The default value stays fixed, so an operator who sources the wrong pins file fails immediately on unset `SPECIAL_` variables rather than silently building delivery inputs.
</context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
