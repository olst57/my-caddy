# Quick Task: Move the upstream watch to a twice-monthly, fork-sourced, quiet-while-open check

The watch currently runs daily, compares the two module SHAs against the
upstream projects, and comments on its tracking issue on every drifting run.
This task moves it to the 1st and 15th at 01:00 UTC, sources the two module
SHAs from this project's own forks (which `fork-sync.yml` keeps in sync with
upstream), and makes both watch workflows do nothing while their issue is
already open. A static test freezes all of that, and the docs stop calling the
watch a daily job.

## Assumptions and boundaries

- `pins/build-inputs.env` is not touched and no pin is bumped (D-07). The
  watcher still only reports.
- Issue #5 is not closed and not commented on (D-07). The owner decides when.
- `fork-sync.yml` keeps its daily `30 1 * * *` schedule, its sync step, and its
  recheck step; only the issue path changes (D-04).
- Drift is still a report, not a red build; only an unreadable source fails a
  run.
- The executor commits locally and does not push or open a PR (D-08).
- Shell files use tabs and `set -euo pipefail`; YAML uses two-space
  indentation; comments explain why a line is load-bearing (AGENTS.md).

## Task 2: Add the static workflow guard and run it in CI

**Files:** `tests/workflows/check.sh` (new),
`.github/workflows/verify.yml`

Create `tests/workflows/check.sh` in the style of `tests/upstream/check.sh` and
`tests/forks/check.sh`: `#!/usr/bin/env bash`, `set -euo pipefail`, a
`REPO_ROOT` derived from `${BASH_SOURCE[0]}`, lower-case helper functions, tab
indentation, a `fail()` that prints `WORKFLOWS-TEST: FAIL - <why>` to stderr and
exits 1, and a final `printf 'WORKFLOWS-TEST: PASS\n'`. It must be offline and
dependency-free: grep and sed only, no network, no jq, no YAML parser.

Target content (keep the comments, they explain the defect each check guards):

```bash
#!/usr/bin/env bash
# Offline static guard for the two scheduled watch workflows.
#
# These checks read the files as text on purpose: no YAML parser, no network,
# no jq. A reverted cron line or a re-added comment path would otherwise only
# surface weeks later on a scheduled run.

set -euo pipefail

REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
UPSTREAM_WATCH="$REPO_ROOT/.github/workflows/upstream-watch.yml"
FORK_SYNC="$REPO_ROOT/.github/workflows/fork-sync.yml"
CHECK_UPSTREAM="$REPO_ROOT/scripts/check-upstream.sh"

fail() {
	printf 'WORKFLOWS-TEST: FAIL - %s\n' "$*" >&2
	exit 1
}

for f in "$UPSTREAM_WATCH" "$FORK_SYNC" "$CHECK_UPSTREAM"; do
	[ -f "$f" ] || fail "missing $f"
done

# The watch runs on the 1st and 15th; a daily cron must not creep back.
grep -Fq "cron: '0 1 1,15 * *'" "$UPSTREAM_WATCH" \
	|| fail "upstream-watch.yml is missing the twice-monthly cron"
cron_count="$(grep -c '^[[:space:]]*- cron:' "$UPSTREAM_WATCH" || true)"
[ "$cron_count" -eq 1 ] || fail "upstream-watch.yml has $cron_count cron entries, expected 1"
if grep -Fq "cron: '0 1 * * *'" "$UPSTREAM_WATCH"; then
	fail "upstream-watch.yml still carries the daily cron"
fi

# fork-sync keeps its daily slot; only its issue path changed.
grep -Fq "cron: '30 1 * * *'" "$FORK_SYNC" \
	|| fail "fork-sync.yml cron changed unexpectedly"

# An already-open issue must silence both workflows: no comment path at all.
for f in "$UPSTREAM_WATCH" "$FORK_SYNC"; do
	if grep -Fq 'gh issue comment' "$f"; then
		fail "$f still has a comment path"
	fi
	grep -Fq 'gh issue create' "$f" || fail "$f is missing the issue creation path"
done

# The two module SHAs come from this project's forks, never upstream. Scope the
# negative check to this script: check-forks.sh compares against upstream by
# design.
grep -Fq 'repos/olst57/forwardproxy/commits/naive' "$CHECK_UPSTREAM" \
	|| fail "check-upstream.sh does not read the forwardproxy fork head"
grep -Fq 'repos/olst57/caddy-l4/commits/master' "$CHECK_UPSTREAM" \
	|| fail "check-upstream.sh does not read the caddy-l4 fork head"
for stale in 'repos/klzgrad/forwardproxy/commits' 'repos/mholt/caddy-l4/commits'; do
	if grep -Fq "$stale" "$CHECK_UPSTREAM"; then
		fail "check-upstream.sh still reads $stale"
	fi
done

# The issue lookup keys on these exact titles; renaming one breaks dedupe.
grep -Fq 'upstream-watch: pinned inputs are behind upstream' "$UPSTREAM_WATCH" \
	|| fail "upstream-watch tracking title changed"
grep -Fq 'fork-sync: module forks are behind upstream' "$FORK_SYNC" \
	|| fail "fork-sync tracking title changed"

printf 'WORKFLOWS-TEST: PASS\n'
```

Wire it into `.github/workflows/verify.yml` immediately after the existing
`Fork sync logic is tested offline` step:

```yaml
      - name: Watch workflows are tested offline
        run: bash tests/workflows/check.sh
```

Do not modify `tests/upstream/check.sh`: its fixtures are generated from
`pins/build-inputs.env`, the `--from` keys and output lines are unchanged, and
it should keep passing as-is. Only add assertions there if Task 1 actually
changes an input it asserts on, which it should not.
