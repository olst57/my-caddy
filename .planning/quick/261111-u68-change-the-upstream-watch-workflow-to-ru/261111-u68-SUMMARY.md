# Quick Task Summary: Twice-monthly, fork-sourced, quiet-while-open upstream watch

**The watch now runs on the 1st and 15th, compares both module SHAs against
this project's own auto-synced forks, and both watch workflows exit silently
while their tracking issue is already open**

## What Was Built

### 1. Watch behaviour and fork-source pins — `0c160a9`

- `scripts/check-upstream.sh`
  - Header rewritten for `--help`: the Caddy tag, `xcaddy` tag and Go release
    stay upstream lookups; the two module SHAs are read from this project's
    own forks because `fork-sync.yml` fast-forwards them from upstream, so the
    fork head is the commit the build would eventually follow.
  - The `--help` print range moved from `2,18p` to `2,24p`; the printed block
    was run and shows the full header with no code and no truncation.
  - Module lookups now read `repos/olst57/forwardproxy/commits/naive`
    and `repos/olst57/caddy-l4/commits/master`. The old upstream
    commit API paths are gone, comments included.
  - Both lookups carry a comment: the forwardproxy one explains the fork is
    the source of truth and why `naive` rather than `master` (master stopped
    in 2024, diverged only by a README edit, permanent false positive); the
    caddy-l4 one says its fork mirrors upstream `master`.
  - `caddy_tag`, `xcaddy_version`, `go_version`, the fixture keys, output
    lines and exit codes are unchanged.
- `.github/workflows/upstream-watch.yml`
  - `cron: '0 1 1,15 * *'`; header says twice-monthly and "while its tracking
    issue is already open, a run does nothing"; no "Daily" or "open or update".
  - `dry_run` description is `'Report only; do not open an issue'`.
  - Step renamed to `Open an issue only when none is open`: it queries the open
    issue by the unchanged title first, prints
    `issue #<n> is already open; no comment and no duplicate` and exits 0 when
    one exists, and only otherwise writes `issue.md` and runs `gh issue create`.
  - The comment branch and its literal command string are gone. Compare step,
    rc handling, `permissions` and the dry-run summary are untouched.
- `.github/workflows/fork-sync.yml`
  - Cron `'30 1 * * *'`, compare, fast-forward, recheck, conditions and token
    handling untouched.
  - Issue step renamed to `Open an issue only when none is open` with the same
    lookup-first shape and the unchanged title
    `fork-sync: module forks are behind upstream`; the body (report, optional
    recheck block, missing-token paragraph, pin note, run URL) is written only
    when no issue exists. The comment branch is gone.

### 2. Offline workflow guard — `30b1492`

- `tests/workflows/check.sh` (new, mode `100644` like the other test scripts):
  grep/sed only, tabs, `set -euo pipefail`, lower-case helpers, `fail()` that
  prints `WORKFLOWS-TEST: FAIL - <why>`, final `WORKFLOWS-TEST: PASS`. It fails
  when the twice-monthly cron is missing or the daily one returns, when
  upstream-watch grows a second cron entry, when fork-sync's cron changes, when
  either workflow has a comment path or loses its create path, when
  `check-upstream.sh` stops reading the fork heads or reads the upstream ones,
  and when either tracking title changes.
- `.github/workflows/verify.yml`: `Watch workflows are tested offline` runs it
  immediately after `Fork sync logic is tested offline`.
- Sensitivity was proved in a throwaway tree, not by trusting a green run:
  baseline PASS, then a restored daily cron, a re-added `gh issue comment`, and
  an upstream-sourced forwardproxy lookup each produced the matching
  `WORKFLOWS-TEST: FAIL` and exit 1.
